## 二、文档不实描述修正

### 2.1 ❌ BUG-013 "ItsmModuleConfig配置类为空" — 不实

**原文档描述**：ItsmModuleConfig配置类为空（迭代1遗留缺陷，轻微）

**实际代码**：ItsmModuleConfig含3个配置属性，且被ItTicketAttachmentController实际使用：
```java
private boolean enabled = true;
private int maxAttachmentsPerTicket = 5;
private long maxAttachmentSizeMb = 50;
```

**结论**：此缺陷不存在，应从缺陷列表中移除。

### 2.2 ⚠️ BUG-012 描述不准确

**原文档描述**：TicketStateMachine.transitionMap未被使用

**实际代码**：transitionMap在TicketStateMachine类内部被4个方法正常使用（canTransit/validateTransition/getAvailableTransitions/getAvailableTargetStatuses）。真正的问题是**WorkflowEngineImpl中注入的ticketStateMachine字段从未被任何方法引用**，属于死依赖。

**修正**：缺陷应描述为"WorkflowEngineImpl注入TicketStateMachine但未使用"，严重程度仍为轻微。

### 2.3 ⚠️ H-01 "通知receiverId修正" 描述不完整

**原文档描述**：receiverId已从creatorId修正为approverId（部分修复）

**实际代码**：receiverId确实改为approverId，但fallback逻辑有严重缺陷：
```java
notification.setReceiverId(ticket.getApproverId() != null ? ticket.getApproverId() : event.getOperatorId());
```
当approverId为null时（工单提交阶段通常如此），通知错误地发给操作者本人，导致审批人收不到通知。

**修正**：此缺陷应升级为"高危"，fallback逻辑导致核心通知功能失效。

### 2.4 ⚠️ H-07 "SLA状态添加RESOLVED" 描述不完整

**原文档描述**：TicketEventListener已设为RESOLVED（部分修复）

**实际代码**：TicketEventListener中确实设置了`record.setStatus("RESOLVED")`，但这是硬编码字符串，项目中**没有SLA状态枚举类**。ItSlaRecord的status字段是String类型，所有状态值（NORMAL/WARNING/BREACHED/RESOLVED）均为散落的字符串字面量，缺乏类型安全保障。

**修正**：应补充"缺少SLA状态枚举类"作为中等缺陷。

## 三、代码审计新发现缺陷

以下缺陷为本次代码审计新发现，原文档未提及。

### 3.1 🔴 严重缺陷（Critical）

#### SEC-01: 工单状态并发修改无保护 — 竞态条件

**位置**：ItTicketServiceImpl.java assignTicket/approveTicket/transitTicket

**问题**：典型的读-校验-写竞态条件。两个操作员同时审批/分配同一工单时，都能通过状态校验，导致状态被覆盖。updateTicketStatus/assignTicket/approveTicket的SQL均无`WHERE status = #{oldStatus}`条件，未使用乐观锁或分布式锁。

**影响**：业务数据一致性风险，工单可能被错误地重复审批或分配。

**修复建议**：在SQL中加入`AND status = #{oldStatus}`条件，或使用MyBatis Plus `@Version`乐观锁，或使用Redis分布式锁。

#### SEC-02: XSS过滤不覆盖/itsm路径

**位置**：application.yml xss.urlPatterns

**问题**：XSS过滤仅配置了`/system/*,/monitor/*,/tool/*`，**完全没有覆盖`/itsm/*`路径**。工单标题、描述、备注等用户输入字段未经XSS过滤，存在存储型XSS风险。

**影响**：攻击者可在工单标题/描述中注入恶意脚本，其他用户查看工单时触发XSS攻击。

**修复建议**：将urlPatterns扩展为`/system/*,/monitor/*,/tool/*,/itsm/*`或直接使用`/*`。

#### SEC-03: CORS配置完全开放

**位置**：ResourcesConfig.java

**问题**：`addAllowedOriginPattern("*")`允许任何域发起跨域请求，攻击者可在恶意网站上发起对ITSM系统的请求。

**修复建议**：将`*`替换为实际的前端域名列表。

### 3.2 🟠 高危缺陷（High）

#### SEC-04: 通知接收人fallback逻辑错误

**位置**：TicketEventListener.java sendNotificationToApprovers/sendNotificationToAssigners

**问题**：当approverId为null时，fallback将receiverId设为event.getOperatorId()（操作者本人），导致：
- SUBMIT时：提交人自己收到"新工单待审批"通知，审批人反而收不到
- APPROVE时：审批人自己收到"工单待分配"通知，分配人反而收不到

**影响**：核心通知功能在关键场景下失效，审批/分配流程受阻。

**修复建议**：SUBMIT时应查询该分类的审批人角色/用户列表；APPROVE时应查询可分配的处理人列表。fallback不应发给操作者本人。

#### SEC-05: JWT Secret硬编码且有规律

**位置**：application.yml

**问题**：JWT密钥直接明文写在配置文件中，且为有规律的大小写+数字交替组合，密钥熵远低于预期。

**修复建议**：使用环境变量注入，生成真正的随机64+字节密钥。

#### SEC-06: 数据库密码明文+root账号

**位置**：application-druid.yml

**问题**：数据库密码`Linfan2714`明文写在配置文件中，且使用root账号连接数据库，违反最小权限原则。Druid监控台密码也是弱密码`123456`。

**修复建议**：使用Jasypt加密配置或环境变量，创建专用数据库账号。

#### SEC-07: 附件下载BUG-007确认存在

**位置**：ItTicketAttachmentController.java download方法

**问题**：Servlet规范规定同一response上getOutputStream()和getWriter()不能同时调用。download方法在异常处理中先调用了getOutputStream()再调用getWriter()，导致IllegalStateException被吞掉。文件不存在时返回HTTP 500+空body，部分写入时可能返回HTTP 200+不完整数据。

**修复建议**：在方法入口处检查文件是否存在，异常处理中不使用getWriter()，改为设置错误状态码即可。

#### SEC-08: Swagger/Druid监控台生产环境暴露

**位置**：SecurityConfig.java

**问题**：Swagger UI和Druid监控台无需认证即可访问，暴露了API结构和数据库执行信息。

**修复建议**：生产环境通过profile禁用，或要求认证后访问。

### 3.3 🟡 中等缺陷（Medium）

#### SEC-09: 全局异常处理器信息泄露

**位置**：GlobalExceptionHandler.java

**问题**：RuntimeException和Exception的处理直接将e.getMessage()返回给前端，可能泄露数据库结构、堆栈信息、内部类名等敏感信息。

**修复建议**：对未知异常返回通用错误消息，详细信息只记录日志。

#### SEC-10: 工单编号生成Redis竞态条件

**位置**：ItTicketServiceImpl.java generateTicketNo()

**问题**：increment和expire不是原子操作，应用在increment之后expire之前崩溃时，key将永远不会过期。

**修复建议**：使用Lua脚本保证原子性，或在key不存在时使用SET key 1 EX 86400初始化。

#### SEC-11: Redis无密码+KEYS命令使用

**位置**：application.yml / RedisCache.java / TokenService.java

**问题**：Redis无密码保护；TokenService使用KEYS命令扫描在线用户token，大数据量下会阻塞Redis单线程导致DoS。

**修复建议**：为Redis设置密码；将keys()替换为SCAN命令；使用Redis Hash结构管理在线用户。

#### SEC-12: FastJson2 AutoType反序列化风险

**位置**：FastJson2JsonRedisSerializer.java

**问题**：序列化时启用WriteClassName，反序列化时启用AutoType。虽然白名单限制为com.itsm包，但Redis被攻破时可触发反序列化攻击链。

**修复建议**：考虑使用Jackson替代FastJson2做Redis序列化，或至少关闭WriteClassName。

#### SEC-13: 文件上传允许HTML文件

**位置**：ItTicketAttachmentController.java

**问题**：允许上传的扩展名包含html/htm，攻击者可上传包含恶意脚本的HTML文件，通过直接访问上传文件URL触发XSS。

**修复建议**：从允许列表中移除html/htm。

#### SEC-14: Druid Wall多语句执行开启

**位置**：application-druid.yml

**问题**：`multi-statement-allow: true`允许一次执行多条SQL语句，是SQL注入攻击的必要条件之一。

**修复建议**：设为false，除非有明确的业务需要。

#### SEC-15: WorkflowEngineImpl注入TicketStateMachine但未使用

**位置**：WorkflowEngineImpl.java

**问题**：注入了ticketStateMachine字段，但整个类中从未引用，属于死依赖。

**修复建议**：移除未使用的@Autowired注入。

#### SEC-16: 缺少SLA状态枚举类

**位置**：ItSlaRecord.java / TicketEventListener.java / SlaMonitorJob.java

**问题**：SLA状态值（NORMAL/WARNING/BREACHED/RESOLVED）均为散落的字符串字面量，缺乏类型安全保障。与工单模块的TicketStatus枚举设计不一致。

**修复建议**：创建SlaStatus枚举类，统一管理SLA状态值。

#### SEC-17: 接口参数校验缺失

**位置**：ItTicketController.java assign/approve方法

**问题**：@RequestBody参数缺少@Validated注解，ItTicket的校验注解放在getter上而非字段上，@Size(min=0)等于没限制最小长度。

**修复建议**：为assign/approve添加@Validated，将校验注解放在字段上，修正@Size(min=1)。

### 3.4 🟢 轻微缺陷（Low）

#### SEC-18: 缺少请求限流/防暴力破解机制

**问题**：除登录接口外，其他API没有全局限流。工单创建、附件上传等接口可被恶意刷量。

#### SEC-19: 缺少HTTPS强制

**问题**：配置中未见HTTPS相关配置，JWT token可能以明文传输。

#### SEC-20: 审计日志完整性无保护

**问题**：操作日志与业务数据同库，可被DBA或SQL注入删除/篡改。

#### SEC-21: XSS过滤器不处理GET请求

**位置**：XssFilter.java

**问题**：GET和DELETE请求的参数不做XSS过滤，仍可能触发反射型XSS。
