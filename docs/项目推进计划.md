## 一、V2.1 核心调整

V2.0 将 Flowable、RabbitMQ、Elasticsearch、Prometheus、Grafana、Docker Compose 全部放入迭代2，技术亮点多，但与当前毕业设计交付节奏不匹配。V2.1 调整为：

| 项目 | V2.0计划 | V2.1计划 | 调整理由 |
|------|----------|----------|----------|
| 工作流 | Flowable 7.x | 自研数据库驱动流程引擎 + 现有状态机校验 | 贴合当前代码，答辩可解释，避免兼容性风险 |
| 消息队列 | RabbitMQ | Spring ApplicationEvent + 通知表持久化 | 单体应用足够，减少中间件运维 |
| 全文搜索 | Elasticsearch | MySQL FULLTEXT/ngram + LIKE兜底 | 迭代3再做知识库搜索，数据量可控 |
| SLA | Flowable Timer + RabbitMQ延迟消息 | Quartz定时扫描 + SLA记录表 | 项目已有Quartz模块，简单可靠 |
| 可观测性 | Prometheus + Grafana | Druid + 日志 + Actuator可选 | 不进入迭代2主路径 |
| 容器化 | 全量 Docker Compose | MinIO阶段性Docker，整体部署文档放收尾 | 避免环境复杂度压垮开发节奏 |

### 9.3 不进入主线的依赖

| 组件 | 状态 | 原因 |
|------|------|------|
| Flowable | 暂不引入 | 当前流程复杂度可控，兼容性需单独验证 |
| RabbitMQ | 暂不引入 | 单体应用用 Spring Event + 通知表足够 |
| Elasticsearch | 暂不引入 | 数据量小，MySQL全文索引更轻 |
| Prometheus/Grafana | 暂不引入主线 | 放到部署增强，不影响核心功能 |
