# 第一部分：项目启动总览

---

## 一、项目背景与目标回顾

### 1.1 项目定位

本项目基于ITSM-Desk 3.9.2脚手架，开发一套面向IT运维场景的工单管理系统，遵循ITIL最佳实践框架，覆盖工单全生命周期管理。作为毕业设计项目，需达到企业级Web应用标准，区别于基础教学类管理系统。

### 1.2 技术栈匹配度现状

根据《技术栈分析与评估报告 V2.1》，当前 ITSM-Desk 技术栈与工单系统需求的总体匹配度约为**70%**。基础后台能力已经覆盖，后续重点不是堆叠中间件，而是补齐流程、SLA、通知和统计等业务闭环能力：

| 匹配等级 | 覆盖维度 | 占比 |
|----------|----------|------|
| 完全满足（5星） | 认证授权、数据权限、CRUD操作、字典管理 | 40% |
| 基本满足（4星） | 操作日志、Excel导出、定时任务、图表统计、文件上传 | 33% |
| 需要扩展（2星及以下） | 实时通知、动态工作流、SLA、全文搜索、邮件短信、变更追踪 | 27% |

### 1.3 核心技术补充决策

| 决策项 | 选型 | 决策理由 |
|--------|------|----------|
| 工作流引擎 | 自研数据库驱动流程引擎 + 现有状态机校验 | 轻量、可控、贴合业务、便于答辩展示 |
| 实时通知 | Spring WebSocket + STOMP | Spring生态原生支持，与JWT认证无缝集成 |
| 事件总线 | Spring ApplicationEvent + 通知表持久化 | 零额外中间件，满足单体应用解耦与通知可恢复需求 |
| 全文搜索 | MySQL FULLTEXT + ngram | 无额外部署，中文分词支持 |
| 邮件通知 | Spring Boot Mail + Thymeleaf | Spring生态原生支持，模板灵活 |
| 短信通知 | 暂不进入主线，作为扩展项 | 避免外部付费服务影响答辩演示，紧急通知先由邮件兜底 |
| 变更追踪 | 自定义变更记录表 | 轻量、可定制 |

### 2.2 环境搭建步骤

#### 步骤1：JDK与Maven配置

```
1. 安装JDK 25，配置JAVA_HOME环境变量
2. 安装Maven 3.9.x，配置MAVEN_HOME和PATH
3. 配置Maven镜像源（阿里云Maven中央仓库）
4. 验证：mvn -version 输出Java版本与Maven版本
```

Maven `settings.xml` 镜像配置：

```xml
<mirror>
    <id>aliyunmaven</id>
    <mirrorOf>*</mirrorOf>
    <name>阿里云公共仓库</name>
    <url>https://maven.aliyun.com/repository/public</url>
</mirror>
```

#### 步骤2：Node.js与前端工具链

```
1. 安装Node.js 24.x LTS版本
2. 配置npm镜像源：npm config set registry https://registry.npmmirror.com
3. 安装pnpm（推荐）：npm install -g pnpm
4. 验证：node -v && npm -v
```

#### 步骤3：MySQL数据库

```
1. 安装MySQL 8.x，配置字符集为utf8mb4
2. 创建数据库：CREATE DATABASE itsm DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
3. 导入RuoYi基础数据脚本（sql/ry_20xxxxxx.sql）
4. 验证：mysql -u root -p -e "SHOW DATABASES;"
```

MySQL关键配置检查（`my.ini` / `my.cnf`）：

```ini
[mysqld]
character-set-server=utf8mb4
collation-server=utf8mb4_general_ci
max_connections=200
innodb_buffer_pool_size=256M
# 全文搜索最小词长（中文建议2）
ft_min_word_len=2
ngram_token_size=2
```

#### 步骤4：Redis

```
1. 安装Redis 8.x
2. 配置密码（requirepass）
3. 配置最大内存策略：maxmemory-policy allkeys-lru
4. 验证：redis-cli ping → PONG
```

#### 步骤5：IDE配置

**IntelliJ IDEA**：
```
1. 安装Lombok插件
2. 安装Alibaba Java Coding Guidelines插件（代码规范检查）
3. 安装MyBatisX插件（Mapper快速导航）
4. 安装Spring Boot Assistant插件
5. 配置代码格式化模板（阿里Java规范）
```

**VS Code（前端开发）**：
```
1. 安装ESLint插件
2. 安装Prettier插件
3. 安装Vue - Official插件
4. 安装Element Plus Snippets插件
```

| 命名规范 | 类名UpperCamelCase，方法名lowerCamelCase，常量UPPER_SNAKE_CASE | 强制 | IDE检查 + Alibaba Coding Guidelines |
| 包命名 | `com.itsm.ticket.{模块}` | 强制 | 编译检查 |

| 方法命名 | 增删改查使用select/insert/update/delete前缀 | 强制 | 代码审查 |
| 注释规范 | 类/接口/公共方法必须有Javadoc | 强制 | IDE检查 |

| 日志规范 | 使用SLF4J + Lombok @Slf4j，禁止System.out | 强制 | 代码审查 |
| API规范 | RESTful风格，统一响应AjaxResult，分页使用TableDataInfo | 强制 | 代码审查 |
| 参数校验 | 使用@Validated + JSR303注解 | 强制 | 代码审查 |
| 数据库规范 | SQL关键字大写，表名字段名小写，业务表前缀it_/wf_ | 强制 | 代码审查 |

## 十三、开发策略原则

### 13.1 核心策略

| 策略 | 说明 | 实施方式 |
|------|------|----------|
| **渐进式开发** | 先基础后高级，先核心后辅助 | 严格按照迭代顺序开发 |
| **风险前置** | 高风险技术点提前验证 | 工作流引擎在迭代2尽早开发 |
| **复用优先** | 最大化复用RuoYi现有能力 | 代码生成器 → CRUD骨架，复用组件 |
| **持续集成** | 每次提交自动构建验证 | 本地构建 + 手动验证 |
| **质量内建** | 测试与开发同步进行 | 每个迭代包含单元测试任务 |

### 13.2 降级策略

当进度滞后或技术方案受阻时，按以下优先级降级：

```
降级优先级：
1. P2功能（流程可视化设计器） → 简化为配置式流程管理
2. P1功能（邮件通知/短信通知） → 降级为仅站内通知
3. P1功能（知识库全文搜索） → 降级为LIKE模糊查询
4. P1功能（报表导出） → 简化为仅Excel导出
5. P0功能（不可降级） → 必须完成
```
